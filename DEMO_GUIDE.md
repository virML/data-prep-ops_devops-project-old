## E. Important viva questions and one-sentence answers

**Why Terraform and Ansible?** Terraform creates AWS resources; Ansible installs/configures software inside the instances.

**What is VPC?** A logically isolated AWS virtual network containing subnets, routes and security groups.

**Why three EC2 instances?** One control host runs Jenkins/Kubernetes/monitoring; two independently process messages, demonstrating a multi-instance VPC and scaling.

**What is IAM?** Identity and Access Management; EC2 roles allow limited S3/SQS/ECR access without storing AWS access keys.

**Why SQS?** It decouples CSV upload from processing and distributes jobs among independently scaling workers.

**Why S3?** Durable private storage for original CSVs, cleaned outputs, job statuses and reports.

**Why Docker?** A reproducible image packages the Python app and dependencies; each runs as a non-root user.

**What does Kubernetes do?** It manages the replicated frontend containers and supports Service-based Blue/Green routing inside Minikube.

**Is this a multi-node Kubernetes cluster?** No. It is a single-host Minikube cluster plus two separate EC2 Docker workers.

**CI vs CD?** CI automatically validates changes; CD automates delivery/deployment after tests and security checks.

**Why Jenkins and GitHub Actions both?** GitHub Actions runs quick source tests; Jenkins performs the controlled AWS deployment and security pipeline.

**Why Maven in a Python project?** The syllabus covers Jenkins/Maven, so a small independent Java CSV-header validator demonstrates Maven without adding unnecessary Java processing logic.

**SonarQube vs Trivy vs ZAP?** SonarQube examines source code, Trivy scans container packages for known CVEs, ZAP passively examines a running web API.

**Does Trivy green stage mean no vulnerabilities?** No. It is report-only in this classroom pipeline; findings must be investigated.

**Does a ZAP baseline report mean the application is secure?** No. It is a short passive scan and does not replace penetration testing or review.

**Why Jenkins credentials and runtime API key?** Tokens stay outside the Git repository, and authenticated endpoints refuse unauthorized calls.

**What is RBAC?** Role-Based Access Control; the demo service account can list Pods but cannot retrieve Kubernetes Secrets.

**Why use SSH tunneling?** The security group permits only admin SSH traffic; sensitive web consoles need not be publicly exposed.

**Prometheus vs Grafana vs CloudWatch?** Prometheus collects app/container metrics; Grafana visualizes them; CloudWatch evaluates AWS queue metrics and drives EC2 scaling alarms.

**What triggers scale-out?** High SQS visible-message backlog crossing a CloudWatch alarm threshold, after evaluation periods.

**What scales exactly?** The EC2 Auto Scaling Group changes the number of worker *instances*; Kubernetes manages frontend *Pods* separately.

**What does Blue-Green mean?** Run old and new versions simultaneously, then switch a Service selector after validation; rollback selects the previous version.

**Why restart kubectl port-forward after the switch?** It may remain attached to an old Pod after the Service selector changes.

**Where are unresolved limitations?** Review README section 15, Trivy/ZAP reports, and any unverified AWS deployment tests.

## G. What to clean up after the final review

On Mac, after backing up approved screenshots/reports, run `terraform -chdir=terraform plan -destroy` and `terraform -chdir=terraform destroy` carefully. Confirm the account/region, and inspect remaining resources/billing. `force_destroy=true` permanently deletes the demo S3 bucket and data. Jenkins/SonarQube/Grafana volume data on the control VM will be lost when terminated.
